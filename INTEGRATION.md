# Підключення реальних даних

1. У Google Sheet на аркуші `Оператори` достатньо колонки `LDAP`; за потреби додайте `Роль`, `Керівник LDAP` і `Команда`. Пошта та `Slack User ID` не потрібні: бот знаходить людину за значенням її Slack-поля профілю `LDAP`.
2. Додайте файл `apps-script/SECURE_API_ADDON.gs` у чинний Apps Script проєкт. У Script Properties створіть властивість `KPI_API_SECRET` з довгим випадковим значенням.
3. Створіть новий Apps Script Web app deployment з URL, який закінчується на `/exec`. Він має запускатися від імені власника таблиці; зовнішній доступ захищений спільним секретом.
4. У Script Properties додайте `SLACK_BOT_TOKEN` зі значенням Bot User OAuth Token. У Slack app додайте Bot Token Scopes `users:read` і `users.profile:read`, потім перевстановіть app у workspace. У кожного оператора поле профілю Slack має мати назву `LDAP` і містити той самий LDAP, що й у таблиці. Після першого вдалого пошуку відповідність кешується в аркуші `KPI Slack cache` на 30 днів.
5. Додайте у секрети хостингу: `KPI_APPS_SCRIPT_URL`, `KPI_APPS_SCRIPT_SECRET` і `KPI_SESSION_SECRET` (щонайменше 32 випадкові символи).
6. Ролі: `operator`, `manager`, `lead`. Для команди менеджера вкажіть LDAP менеджера в `Керівник LDAP`.

Не зберігайте LDAP-паролі. Сайт створює одноразове посилання, відправляє його у Slack DM, а Apps Script зберігає лише хеш токена та позначає його використаним після входу.

## Дані за місяцями

- У `Показники` кожен місяць починайте **новим рядком заголовків**: в A — `Серпень 2026`, у тому ж рядку — `Оператор`, `LDAP`, `Звернень`, `AT`, `SL` та інші колонки. Саме такий формат на скриншоті коректний. LDAP має бути один раз на оператора в кожному місяці.
- У `Кріти` та `Зауваження` рекомендовано додати колонку `LDAP` і заповнювати її. Обов'язково вказуйте дату або `Період`/`Місяць`; запис без визначеного місяця не буде зарахований до іншого періоду. Якщо LDAP немає, використовується точний збіг ПІБ оператора.
- У `Рекомендації` використовуйте колонки: `LDAP | Рекомендація | Період`. Для періоду вводьте `2026-08` або `Серпень 2026`. Порожній період означає загальну рекомендацію, яку буде видно в усіх місяцях цього оператора.
- Рівень самостійності адміністратор задає в кабінеті після вибору місяця. Система автоматично створює лист `KPI independence by period` з полями `LDAP | Період | Рівень самостійності | Оновлено`. Старий лист `KPI cabinet profiles` не змінюється: значення з нього працюють як загальне резервне значення.

## Адміністративні дані

Адмінка автоматично створює додаткові листи лише під час першого збереження:

- `KPI development plans` — персональні кроки донавчання за LDAP і місяцем;
- `KPI targets` — цілі KPI за напрямком (`ALL` — для всіх);
- `KPI cabinet audit` — журнал усіх змін, зроблених через адмінку. Він не змінює вихідні KPI-дані.
