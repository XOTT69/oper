# План: особистий KPI-кабінет оператора

## Мета

Оператор входить за LDAP через одноразове посилання у Slack і бачить лише власні KPI, рекомендації та навчальні матеріали. Менеджер бачить свою команду, керівник — свій напрямок. Дані не передаються в браузер до успішного входу.

## Архітектура

- **Frontend і серверний API:** Next/Vinext на Cloudflare Sites.
- **Джерело KPI:** чинна Google Sheet, яку вже читає Apps Script.
- **Авторизація:** LDAP вводиться в кабінеті → Slack-бот надсилає одноразове посилання → сайт створює захищену 8-годинну сесію.
- **Контроль доступу:** Apps Script на сервері фільтрує дані за LDAP і роллю до відповіді сайту. Клієнт не отримує записи інших операторів.
- **GitHub:** `github.com/XOTT69/oper` — єдине джерело коду. Секрети не зберігаються в репозиторії.

## Етапи

1. **Відновити й зафіксувати базу**
   - Перенести перевірений код кабінету та Apps Script у GitHub.
   - Додати `.env.example`, інструкцію запуску та опис конфігурації Slack/Apps Script.
   - Не включати OAuth-токени, Telegram-токени, URL з секретами або дані операторів.

2. **Закрити стартовий екран**
   - До Slack-входу показувати лише сторінку входу, без демо-KPI.
   - Після входу показувати ім'я, роль і дані, дозволені для LDAP.
   - Додати вихід із сесії та зрозумілий стан простроченого посилання.

3. **Підключити реальні KPI та рекомендації**
   - Використати наявні аркуші `Показники`, `Рекомендації`, `Кріти`, `Зауваження`.
   - Показати динаміку KPI, поточні показники, критичні теми та персональні рекомендації.
   - Винести навчальні матеріали й корисні посилання до аркуша `KPI Посилання`: назва, URL, категорія, напрямок, роль, активність.

4. **Ролі й адміністрування доступу**
   - `operator`: тільки власні дані.
   - `manager`: власні дані та оператори з його `Керівник LDAP`.
   - `lead`: дані свого напряму.
   - Доступ видається рядком LDAP в `Оператори`; відсутній або вимкнений LDAP не отримує Slack-посилання.

5. **Надійність і безпека**
   - Одноразові посилання діють 10 хвилин; у таблиці зберігається лише їхній хеш.
   - Сесійна cookie має `HttpOnly`, `Secure`, `SameSite` і короткий строк дії.
   - Усі виклики до Apps Script підписані спільним серверним секретом.
   - Slack-ID кешується після першого LDAP-пошуку, щоб наступні входи були швидкими.
   - Додати журнал технічних подій без токенів і персональних KPI.

6. **Запуск і підтримка**
   - Публікація сайту з GitHub у Cloudflare Sites/Workers.
   - Оновлення: зміна в GitHub → автоматична або ручна публікація перевіреної версії.
   - Apps Script лишається в поточному KPI-проєкті та читає наявну таблицю.

## Порядок першого релізу

1. GitHub-репозиторій і документація.
2. Закритий екран входу та реальні дані після Slack-OTP.
3. Вкладки KPI, рекомендацій, помилок і матеріалів.
4. Аркуш корисних посилань і ролі менеджерів/керівників.
5. Перевірка на двох LDAP: оператор і менеджер.
